# 库尾淹没切换与 W2 精细化改造方向
本页回答什么问题：库尾河流段并不是始终处于单一“河流态”，高水位时它确实会被淹没；那么 W2 到底是在哪个阶段最容易失真，为什么会显得“简单而离散”，以及若要把它改得更精细，最值得改哪些地方。
Updated: 2026-04-17

## 1. 先纠正一个容易误解的点

- 你这个库尾段不是“始终天然河道”，也不是“始终平库区”。
- 更准确地说，它会在三个水力状态之间切换：
- `河流控制态`：低水位、快流、较大沿程坡降，上游坝下河槽控制明显。
- `过渡回水态`：下游顶托开始向上游推进，回水末端在库尾附近来回迁移，部分河段接近天然河道，部分河段已受淹没回水控制。
- `淹没库区态`：高水位时库尾段被淹没，水面线变缓，更接近库区/回水区响应。

- 所以问题不能表述成“W2 不会模拟淹没”。
- 更准确的说法是：W2 对`淹没库区态`相对更能接受，但对`河流控制态`和尤其是`过渡回水态`的连续切换处理得太离散。
- 你的 case 最难的恰恰不是高水位本身，而是“河流态-过渡回水态-淹没态”的反复切换。

## 2. W2 为什么在高水位淹没段相对还行

- W2 的主设计目标本来就偏向细长水库、河道型水库和分层水体。
- 在高水位淹没条件下，流动的主控量更接近：
- 自由液面变化。
- 库容响应。
- 分层与垂向混合。
- 结构物流量和整体水量守恒。

- 这和 W2 的代码设计是匹配的：
- laterally averaged。
- hydrostatic。
- 自由液面隐式求解优先。[w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:843)
- 速度再通过动量方程和连续性修正补齐。[w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:1276) [w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:1317)

- 换句话说，当库尾已经充分淹没时，W2 更像在做它擅长的事情：求一个细长库区中的自由液面和分层流场。

## 3. W2 为什么在库尾过渡段最容易失真

## 3.1 它把回水前缘当成“活动段开关”，而不是连续迁移的湿润前缘

- 代码里不是让每个段始终存在，只是水深很浅；而是通过 `CUS(JB)` 维护“当前活动上游段”。[init-geom.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/init-geom.F90:484)
- `layeraddsub` 会在运行中做 `Add segments / Subtract segments`。[layeraddsub.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/layeraddsub.F90:53) [layeraddsub.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/layeraddsub.F90:1024)
- 这意味着 W2 处理库尾前缘的方式更像：
- “这个段现在算不算进活动水体？”
- 而不是：
- “这个段始终存在，只是局部水深、坡降和控制机制在连续变化。”

- 对库区这不是大问题。
- 但对回水末端迁移，这是一个结构性弱点，因为真实物理过程是连续湿润/淹没的，而不是整段突然变成 `-999` 再突然恢复。

## 3.2 一旦活动边界后退，物理边界和来水位置也一起后退

- 初始化和主求解里，上游边界都是按 `IU = CUS(JB)` 处理的。[init-u-elws.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/init-u-elws.f90:26) [w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:903)
- 支流入流位置也会被钳制到 `MAX(ITR, IU)`。[hydroinout.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/hydroinout.F90:858)
- 这会带来一个非常重要的后果：
- 真实世界里，库尾河流段仍然存在，只是被顶托。
- 代码世界里，一旦这个段退出活动域，边界和来水就直接从更下游的位置进入。

- 所以 W2 在这里失真的本质，不只是“把一个段算干了”，而是“把整个上游河流段在计算上缩短了”。

## 3.3 自由液面先解、速度后修正，会把很多误差折算成“平一点的水面线”

- 主循环顺序是：先自由液面，再纵向速度，再连续性修正，再诊断垂向速度。[w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:843) [w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:1129) [w2_main.f90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/w2_main.f90:1335)
- 这种分裂推进对库区是高效的。
- 但在过渡段，它有个典型副作用：为了先保证自由液面和总体体积响应，模型更容易通过后续 `QC` 修正把流场调平，而不是保留真实的河流态沿程坡降。

- 这也是为什么最小实验集里你能看到：
- `common-mode` 可以被明显改善。
- 但 `differential-mode` 仍持续很差。[09_structural_minimal_test_set.md](/C:/Users/NING/Desktop/v455/docs/reference/hydrodynamics_limitations/09_structural_minimal_test_set.md:1)

## 3.4 它的几何和干湿表达是“按段、按层、按阈值”的，不是连续湿润率表达

- 在代码里，层和段的活跃性是通过阈值和层索引判断的。[init-geom.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/init-geom.F90:466) [layeraddsub.F90](/C:/Users/NING/Desktop/v455/w2source_v455_2_11_2026/layeraddsub.F90:45)
- 这意味着：
- 水面前缘的位置是按 segment 和 layer 的整数级别跳动的。
- 入流、面积、糙率响应也是按活动/非活动两种状态切换的。

- 所以你会感觉它“很简单很离散”，并不是因为它没有水动力学，而是因为它采用的是一种适合库区的大尺度离散表达，而不是连续细腻的湿润前缘表达。

## 4. W2 哪些地方其实不是“太简单”，而是“简化得很有针对性”

- 这里也需要公平一点。
- W2 不是粗糙地“随便算一算”，它的很多简化是有明确目标的：
- 用 hydrostatic 假设换取对长条形分层水体的稳定求解。
- 用 laterally averaged 换取对纵向-垂向过程的高性价比模拟。
- 用活动层/活动段管理换取在水位大起伏时仍能维持数值稳定。
- 用 distributed tributary 换取 ungaged inflow 的工程闭合能力。

- 这些设计在库区都很合理。
- 真正的问题是：你的库尾段不只是库区，也不只是河道，而是一个反复切换控制机制的过渡带。

## 5. 哪些改造能让它更精细

下面按“收益/代价”分层讲。

## 5.1 第一层：最值得优先做的改造

### A. 固定物理上游边界，不再让 `SEG 2` 跟着 `CUS` 后退

- 这是最关键的。
- 应该引入一个“物理上游边界段”和“数值活动起算段”的解耦。
- 对这个 case，`SEG 2` 到某个上游控制段应被定义为永久湿润或永久参与计算的 river reach。
- 即使很浅，也不允许主边界和来水位置后退到 `SEG 3`、`SEG 4` 以后。

为什么值：
- 这是直接对着病根下手。
- 能保证库尾河流段始终存在于求解域里。

副作用：
- 很浅水时数值稳定性会变差。
- 需要给极浅段设置最小厚度、最小面积、最小水力半径保护。

### B. 把“Add/Subtract segments”改成连续 wetting/drying + 迟滞

- 现在是段级开关。
- 更精细的做法应该是：
- 设置 `h_on` 和 `h_off` 两个阈值，避免反复抖动。
- 在浅水段引入最小湿润深度或湿润率，而不是直接退出活动域。
- 允许 very shallow but active 的状态存在。

为什么值：
- 回水前缘迁移会更连续。
- `SEG 2` 不会再表现成“突然出现”的新水段。

副作用：
- 代码改动比 A 大。
- 需要更仔细地保护 `BHR/BH/VOL/U/W` 的数值稳定。

### C. 来水位置按物理位置固定，不能再用 `MAX(CUS, ITR)` 硬钳制

- 上游主边界、支流、withdrawal 的位置都应区分：
- 物理位置。
- 当前局部湿润单元。

- 更合理的做法是：
- 先保留物理位置。
- 若目标单元极浅，则在局部若干湿单元之间连续分配，而不是整体下移到新的 `CUS`。

为什么值：
- 来水动量和位置不再随着活动段后退。
- 这对库尾河流态尤其关键。

副作用：
- 需要重写一部分入流/出流放置逻辑。

### D. 每步内增加 hydro inner iteration

- 现在是一次 `HYDROINOUT -> 水面 -> U -> QC -> W`。
- 更精细的做法是每步做 2 到 4 次 Picard 迭代：
- 更新源汇。
- 解自由液面。
- 更新 `U/QC`。
- 检查水面、流量、活动段是否收敛。

为什么值：
- 减小“边界先变了、水面跟上了、速度再补”的时间滞后。
- 对河流态-回水态切换特别有帮助。

副作用：
- 计算量增加。
- 若活动段仍然是开关式，迭代效果会被限制，所以最好和 A/B 配套。

## 5.2 第二层：会明显提升精细度，但改动更大

### E. 对库尾过渡带采用更细的纵向和垂向离散

- 这不是简单说“网格再密一点”。
- 更精细的方向是：
- `SEG 2-58` 或更长过渡带采用更短 `DLX`。
- 垂向层高在库尾段显著减小。
- 尽量减少“前缘一跳就是整段、整层”的量化误差。

为什么值：
- 回水前缘位置和局部坡降会更连续。

副作用：
- 只加密网格而不改 A-D，效果有限。
- 计算量显著上升。

### F. 给库尾段单独的河道态/淹没态混合闭合

- 现在 W2 用的是统一的库区式框架。
- 更精细的思路是对 transition reach 加一个局部模式：
- 浅水、陡坡时偏河道控制。
- 深水、缓坡时偏回水/库区控制。
- 中间用连续 blending，而不是切换。

为什么值：
- 更贴合你这个段的真实物理属性。

副作用：
- 属于方法层改造，不再只是“小修小补”。

## 5.3 第三层：如果追求最高真实性，应考虑混合模型

### G. 库尾段单独接一个 1D 动波子模型

- 如果最终目标是把库尾天然河流态做准，而库区分层和水温仍然交给 W2，
- 最自然的路线其实是：
- 库尾过渡带用 1D 非恒定回水/动波求解。
- 下游库区继续用 W2。
- 两者在连接断面交换流量、水位和温度。

为什么值：
- 这是从模型设计目标上解决错位问题。

副作用：
- 工程复杂度大。
- 不再是纯 W2 单模型。

## 6. 对你这个 case，我会怎么排序

如果目标是“尽量不脱离 W2，但要让库尾段更像真实物理”，我会按这个顺序做：

1. 固定物理上游边界，禁止 `SEG 2` 后退。
2. 把 segment add/sub 改成带迟滞的连续 wetting/drying。
3. 让上游主边界和支流位置按物理位置入流，不再跟着 `CUS` 走。
4. 增加每步内的 hydro 迭代。
5. 只对库尾过渡带做局部网格加密。

如果做到这 5 步后，库尾段坡降仍明显塌缩，那就说明单靠 W2 这套框架已经到顶了，下一步就应该认真考虑“尾段 1D、库区 W2”的混合方案。

## 7. 最终判断

- 你提出“库尾河流段高水位时也会被淹没”这个补充非常重要。
- 它说明问题不是“W2 不会算淹没回水”，而是“W2 不会连续地算好从河流态到淹没态的迁移过程”。
- 这就把解决方向也限定得更清楚了：
- 不是单纯再调参数。
- 不是简单再补 distributed。
- 而是要把库尾段从“活动段开关逻辑”里解放出来，让它变成一个始终存在、连续湿润、边界位置固定的过渡河道。
