# Hybrid Tailreach 第二阶段完成蓝图
本页回答什么问题：在已经完成 `V0-V10` 原型验证之后，如何把当前“尾段半成品”推进成一个真正可持续开发、可验证、可止损的 Hybrid Tailreach 方案。

Updated: 2026-04-18

## 1. 这份续写蓝图为什么需要单独存在

原始蓝图 [15_w2_hydrodynamic_upgrade_blueprint.md](/C:/Users/NING/Desktop/v455/docs/reference/hydrodynamics_limitations/15_w2_hydrodynamic_upgrade_blueprint.md:1) 已经明确了总方向：

- 先修语义
- 再修前沿
- 再修耦合
- 最后进入 `Hybrid Tailreach`

但现在代码已经推进到 `V10`，说明我们不再停留在“是否需要局部尾段子模型”的论证阶段，而进入了“如何把它做完整”的实施阶段。

也就是说，当前缺的不是再重复原蓝图，而是：

- 把 `Hybrid Tailreach` 从方向级目标，细化成结构级蓝图
- 把之前已经试过并验证过的路径固定下来
- 把接下来不能再反复试错的部分，明确写成有阶段、有边界的完成路线

这份文档就是这个用途。

## 2. 当前代码已经走到哪里

截至 `V10`，当前程序已经不是原版 W2，而是：

- 一个保留主库区 `laterally averaged + hydrostatic` 求解的原版 W2 主链
- 外挂一个“受保护的局部尾段子系统”
- 再加上前沿状态机、尾段 stage、尾段 storage、尾段有效出流与主库区入流耦合

它已经具备的能力是：

1. `SEG 2` 不再只会输出 `-999`
2. `SEG 2` 和 `SEG 222` 都能做双站点对比
3. 尾段 water level、front state、主边界反馈、有效出流耦合都已经被独立验证过
4. 让尾段 effective discharge 真正影响主库区入流之后，水面差开始出现实质改善

它还没有具备的能力是：

1. 河流段-过渡段-库区段长度的连续动态求解
2. 过渡段内部的独立 discharge / momentum 演化
3. 尾段内部多断面传播
4. 与主库区的真正强耦合联立
5. 同时把 `SEG 2`、`SEG 222`、两点水面差三者一起做好

所以当前状态最准确的定义是：

- `hybrid tailreach prototype`

而不是：

- `hybrid tailreach solver`

## 3. 第二阶段的总目标

第二阶段的目标不是再多加几个 patch，而是把当前原型推进成一个真正成立的局部尾段 reach 模型。

必须同时满足三条：

1. **物理上**
   库尾应该允许在固定物理域内连续表现三种状态：
   - 河流控制态
   - 过渡回水态
   - 淹没库区态

2. **数值上**
   这些状态的变化必须来自：
   - 当前水位
   - 当前来流/出流
   - 当前局部坡降和流速

   而不是来自：
   - 活动段拓扑开关
   - 单一经验补偿流量
   - 固定 branch slope 的强行前推

3. **工程上**
   最终必须同时用三项指标验收：
   - `SEG 2`
   - `SEG 222`
   - `SEG 2 - SEG 222`

## 4. 第二阶段的核心原则

### 4.1 不再继续堆弱补丁

`V8-V9` 已经证明：

- 尾段 stage 同步给前沿
- 尾段 stage 弱反馈给主边界

都能稳定，但效果有限。

所以从现在开始，不再把“再加一个弱反馈补丁”当作主路线。

### 4.2 不把过渡段当固定长度

过渡段不是固定某几个 segment，而应该理解为：

- 固定物理域内的动态状态带

因此第二阶段不应继续问：

- “过渡段到底是 2-3 段还是 2-10 段”

而应问：

- “固定尾段物理域里，每个断面当前处于什么控制状态”

### 4.3 先做局部 1D reach，再谈更强耦合

现在最大缺口不是再调一个 coupling relax，而是尾段内部没有真正的 discharge / momentum 状态。

所以第二阶段的主路线必须是：

- 先把尾段内部 reach 立起来
- 再把 reach 与主库区的耦合从弱耦合推进到强耦合

## 5. 第二阶段的目标架构

目标架构如下：

### 5.1 固定尾段物理域

不再只盯 `SEG 2 -> SEG 3` 这一条链接，而是定义一个固定尾段计算域：

- 从 `IUPHYS(JB)` 起
- 到主库区起算断面之前若干段

这段物理域始终存在，不再允许被活动段裁掉。

### 5.2 尾段内部状态

尾段内部至少要有两类状态：

1. **几何/水位状态**
   - `stage`
   - `depth`
   - `storage`
   - `wetted area`

2. **流量/动量状态**
   - `discharge`
   - 必要时扩展成 `momentum-like state`

如果第二阶段只保留 storage continuity，而没有独立 discharge state，那么它仍然只是“加强版 rating curve reach”，还不算完成。

### 5.3 过渡段状态判别

每个尾段断面都应该有一个连续状态指标，用于表达它当前更偏向：

- 河流控制
- 回水过渡
- 淹没库区

这个状态不应该由单一阈值决定，而应综合：

- 局部水深
- 水面坡降
- 床坡与水面坡的相对关系
- 流速或 Froude 数
- 下游顶托强度

### 5.4 与主库区的交换量

尾段与主库区之间必须至少交换：

- 上游连接断面的 stage
- 下游连接断面的 stage
- reach 向库区释放的 discharge

可选增强项：

- 温度层分配
- 密度修正
- 多层入流分配

### 5.5 耦合顺序

推荐的目标顺序是：

1. 主库区读到上一轮尾段边界
2. 主库区完成一步自由液面和速度
3. 尾段 reach 用新的主库区边界更新自己的 stage / discharge
4. 尾段出流回写主库区边界
5. 在同一时间步内做 1-2 次弱内迭代

这比当前“主库区一步 + 尾段后处理一步”的关系更完整。

## 6. 第二阶段的版本束

为了保持计划性，建议把第二阶段拆成 4 个版本束。

### 6.1 `V11: Fixed Tail Domain`

目标：

- 把尾段从“单链接对象”升级成“固定尾段物理域”

必须完成：

- 定义固定尾段计算域的起止
- 不再把尾段长度隐含在 `FRONT_SEG / TAIL_UPSEG / TAIL_DNSEG`
- 输出尾段域内每个断面的状态

验收：

- 尾段域长度固定
- 活动段变化不再改变尾段物理域存在性

### 6.2 `V12: Reach State Evolution`

目标：

- 让尾段内部不只靠 storage continuity，而有独立 discharge evolution

必须完成：

- 引入 tail discharge state
- 引入最小 1D reach 演化关系
- storage 和 discharge 共同更新，而不是一主一从

验收：

- 尾段出流不再只是 rating-style algebraic output
- 尾段内部状态演化有时间记忆

### 6.3 `V13: Transition-State Reach`

目标：

- 让尾段内不同断面连续表达河流态-过渡态-库区态

必须完成：

- 定义连续状态指标
- 用状态指标控制局部阻力、有效断面、出流关系
- 把前沿状态机从“外部 patch”逐步并入 reach 内部状态

验收：

- `FRONT_STATE` 不再单独承担主要物理职责
- 过渡段位置由 reach 状态自然表现

### 6.4 `V14: Stronger Coupled Hybrid`

目标：

- 把尾段 reach 和主库区从弱耦合推进到更强耦合

必须完成：

- 尾段 discharge 真正控制主库区入流
- 尾段上游/下游 stage 在同一步内完成至少一次更新
- 保留必要的松弛和回退机制

验收：

- 双站点和两点水面差同时出现实质改善
- 长窗稳定

## 7. 第二阶段不再做的事

为了避免重新陷入试错，明确以下内容不再作为主路线：

- 不再单独加新的 weak feedback patch
- 不再单独调 `distributed`
- 不再单独调全局糙率去修尾段
- 不再把 `SEG 2` 单点输出本身当作阶段目标

这些都可以继续作为辅助手段，但不再是主开发方向。

## 8. 当前的中间结论如何继承

第二阶段必须继承以下已经被验证过的结论：

1. 原版 W2 最大问题之一是 `SEG 2` 不在主求解域
2. 仅靠输出覆盖不能解决真实水面线
3. 仅靠 front-state 同步和弱边界反馈效果有限
4. 让尾段 effective discharge 真正进入主库区入流后，水面差开始改善
5. 但当前 `storage + rating + relaxed coupling` 还不够

## 9. 当前推荐的开发基线

如果接下来进入第二阶段实现，建议把当前基线固定为：

- 保留 `V0-V9` 的全部语义层改造
- 保留 `V10` 的尾段 storage / inflow / outflow 架构
- 当前耦合强度以 `TAIL_FLOW_COUPLING_RELAX = 0.15` 作为临时基线

原因是：

- 它不是最好看的指标
- 但它是在“坡降改善”和“绝对水位不过度恶化”之间最平衡的候选

## 10. 第二阶段的止损条件

如果做到 `V12-V13` 之后仍然出现下面任一条，就要暂停而不是继续加 patch：

1. `SEG 2`、`SEG 222`、`DIFF` 三者仍不能同时改善
2. 尾段 reach 每加强一步，长窗稳定性就明显恶化
3. 尾段内部状态越来越多，但物理解释越来越弱

这意味着需要重新讨论：

- 是不是要把 Hybrid Tailreach 独立成更完整的 1D 模块，而不是继续嵌在当前单文件主程序里

## 11. 最后的结论

这份续写蓝图的核心，不是宣布前面的尝试失败，而是明确：

- `V0-V10` 已经把方向验证到足够深了
- 继续往前不能再靠零碎 patch
- 接下来应该进入真正的第二阶段：
  - 固定尾段物理域
  - 建立 reach 内部状态
  - 让过渡段成为 reach 内部的动态状态带
  - 再把它与主库区更强地拼接

换句话说：

第一阶段已经证明“尾段要单独算”；
第二阶段要解决的是“怎样把它算完整”。
