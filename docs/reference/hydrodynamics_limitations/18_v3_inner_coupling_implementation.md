# V3 步内内耦合实现记录
本页回答什么问题：在 `V2` 连续前沿之后，这一版到底给 W2 增强了什么“步内内耦合”能力、为什么没有直接采用完整双次水动力推进、以及现在这版真实能做什么。

Updated: 2026-04-18

## 1. 这一版的真实定位

这次没有把 `w2_main` 改成完整的双次水面-速度联立求解器。

我先尝试过一个更激进的 `V3`：

- 每个时间步内做两次完整的
  - `HYDROINOUT`
  - 自由液面解
  - 纵向速度解
  - 垂向速度解

结果在当前 XLD smoke case 上会迅速失稳，出现：

- `MAX_DZ` 和 `MAX_DQ` 快速放大
- 主干上游活动段提前收缩
- 负表层厚度
- `w2.err`

所以最终保留下来的 `V3` 是一个更保守但可运行的版本：

- 第一遍仍按当前 W2 主水动力完整计算
- 在第一遍完成后，基于更新后的水位，再执行第二次 `HYDROINOUT`
- 记录第二次源汇刷新和第一次之间的差异
- 但**不再做第二次完整水动力推进**

这意味着当前 `V3` 的真实意义是：

`源汇刷新内耦合骨架`

而不是：

`完整双次水动力内迭代`

## 3. 当前 V3 做了什么

在每个时间步里：

1. 先执行原始的一遍完整主水动力计算。
2. 保存第一遍后的 `QIN`。
3. 写一条：
   - `[V3_INNER_ITER] PASS=1`
4. 清零 `QSS`。
5. 再用更新后的当前状态执行第二次 `HYDROINOUT`。
6. 比较第二次和第一次的 `QIN` 变化。
7. 写一条：
   - `[V3_INNER_ITER] PASS=2 MAX_DQIN=...`

也就是说，这一版现在真实耦合的是：

- `更新后的水位/状态`
- `再次计算的源汇`

而不是：

- `更新后的水位`
- `再次推进的整套水动力`

## 4. 为什么要收缩到这个版本

原因很明确：完整双次推进在当前求解框架下不稳定。

从 smoke 调试结果看，第二次完整推进会把当前时步的更新当成新的“旧时刻状态”继续推进，导致：

- 水位增量被过度放大
- 流量校正被重复推动
- 活动段边界过早收缩
- 表层厚度变负

换句话说，这不是“多迭代一遍就更准”，而是当前 W2 的离散组织方式决定了：

- 完整双次推进会把同一时间步推进得过头

所以现在保留下来的 `V3` 是一个稳定的中间版本：

- 先把源汇刷新再走一遍
- 先把诊断和接口立起来
- 不强行把整套主求解重复推进到不稳定区

## 5. 新增日志

当前新增并稳定保留的是：

- `[V3_INNER_ITER] PASS=1`
- `[V3_INNER_ITER] PASS=2 MAX_DQIN=...`

在当前 smoke 窗口里，`MAX_DQIN` 还是 `0.0000`，这说明：

- 第二次 `HYDROINOUT` 至少在当前这个短窗里，没有引入额外的主干入流量变化

这件事本身也很重要，因为它告诉我们：

- 当前 smoke 窗口里，`HYDROINOUT` 的主干边界量级还不敏感
- 未来若要继续推进 V3/V4，就需要把关注点放到更敏感的结构物流量、局部回水和更长窗口上

## 7. 这版的提升与限制

### 已经提升的地方

- 步内已经存在第二次 `HYDROINOUT`
- `w2.wrn` 已经能看见明确的 `V3` 内耦合标记
- 当前版本不再只是单次源汇刷新后直接向后走

### 还没有做到的地方

- 没有第二次完整自由液面求解
- 没有第二次完整速度推进
- 没有结构物流量的收敛判据
- 没有 `ELWS/Q/structure flow` 的真正步内收敛控制

所以，这一版严格来说属于：

- `inner-coupling scaffold`

而不是：

- `inner-coupled hydrodynamic solver`

## 8. 对下一步的含义

这一版已经给下一步提供了两个很清楚的方向：

1. 继续增强步内耦合，但要避免“第二次完整推进导致时步过推进”。
2. 把 `V4/V5` 的几何连续化和状态闭合做进去以后，再考虑更强的内迭代。

如果直接在当前框架上硬推完整双次水动力，很容易再次不稳定；所以更合理的顺序是：

- 先让几何和前沿状态更连续
- 再让完整内迭代更强

这也说明蓝图里的先后顺序是对的：  
`V2 -> 保守 V3 -> 更连续几何/状态 -> 更强完整内迭代`
