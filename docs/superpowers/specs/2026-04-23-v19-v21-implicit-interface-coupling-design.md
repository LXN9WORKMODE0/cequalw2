# V19-V21 Implicit Interface Coupling Design

本页回答什么问题：在 `V18` 已经证明“多段 tailreach 强耦合功能成立，但时间步刚性明显增强”的前提下，如何转入更成熟的接口处理路线，把当前的分裂 predictor/corrector 原型推进成一个更接近整体隐式、真正收敛的 free-surface interface solver。

Updated: 2026-04-23

## 1. 为什么现在要转方案 1

到 `V18` 为止，我们已经验证了三件重要的事实：

- tailreach 的多段 state、逐段 transition-state 和更强的接口耦合都已经能真实进入运行链。
- `V18` 的 predictor/corrector、segmentwise output 和 interface handoff 在功能上是成立的。
- 但一旦耦合做强，运行代价显著上升，短窗都已经出现明显的时间步刚性问题。

对应诊断见：

- [34_v18_performance_rigidity_diagnosis.md](/C:/Users/NING/Desktop/v455/docs/reference/hydrodynamics_limitations/34_v18_performance_rigidity_diagnosis.md:1)

这个诊断已经说明：

- 日志风暴不是主因
- predictor/corrector 调度频率也不是主因
- 真正的主因更像是主库区在更强接口条件下变得更“刚”

因此，继续沿方案 3 做外围减载，边际收益已经明显下降。  
现在更合理的是转向更成熟的接口处理方法，也就是方案 1。

## 2. 方案 1 的目标

方案 1 的目标不是再加新的功能层，而是改变接口的求解方式。

更准确地说，它要把当前：

- “tail predictor 一次”
- “reservoir solve 一次”
- “tail corrector 一次”

这种一步一往返、界面不真正收敛的分裂方法，推进成：

- 以接口残差为核心
- 每个时间步内做真正的界面收敛
- 尽量减少靠极小时间步硬磨过去的现象

## 3. 方案 1 在水动力学上的定位

方案 1 不是直接把整个 W2 改写成全新的 1D/2D 动波求解器，而是在当前代码结构下，尽量靠近成熟的 free-surface / barotropic 接口处理方法。

它吸收两类成熟思想：

### 3.1 强耦合界面迭代

接口上的 `stage` 和 `discharge` 不能只交换一次就进入下一时间步。  
更成熟的做法是：

- 明确构造界面残差
- 在每个时间步内对界面状态做多次修正
- 直到 `WSE/Q` 残差收敛

### 3.2 更接近整体隐式的接口更新

当前做法本质上还是分裂 predictor/corrector。  
方案 1 的目标是逐步把接口更新从“经验性往返修正”推进到“更接近隐式校正”的形式。

在当前代码基础上，最现实的做法是：

- 不直接重写全局矩阵
- 先在接口层构造一个低维、可反复修正的隐式近似

## 4. 为什么这条路更成熟

现在的 `V18` 属于“one-pass partitioned coupling”：

- 每个时间步里接口只做一次 predictor/corrector 往返
- 没有真正的界面收敛判据
- 界面量的最终一致性更多靠后续很多小时间步慢慢修正

而方案 1 的成熟性在于：

- 它把“很多小时间步修正”改成“同一步内做更充分的界面收敛”
- 让时间步承担的是时间推进，而不是承担界面残差迭代

这在数值水动力学上更合理。

## 5. 目标接口未知量

方案 1 不从全域所有变量入手，而先锁定最核心的接口未知量：

- `ETA_INT`：接口自由液面/水位
- `Q_INT`：接口流量

在当前代码语义下，可近似理解为：

- `ETA_INT ~ TAIL_WSE_DN / reservoir upstream head`
- `Q_INT ~ TAIL_Q_LINK`

这两个量是最敏感、也最能代表接口一致性的核心变量。

## 6. 目标算法骨架

### 6.1 V19：接口残差显式化

第一步不改求解器本质，而是先把接口收敛问题从“隐性感觉”变成“显性诊断量”。

每个时间步内，记录并输出：

- predictor 后的接口 `ETA/Q`
- reservoir 更新后的接口 `ETA/Q`
- tail corrector 后的接口 `ETA/Q`
- 对应残差

目标是回答：

- `V18` 到底在哪个接口量上最不收敛
- 残差是衰减型还是振荡型

### 6.2 V20：真正的界面强耦合迭代

在同一时间步内不再只做一次 predictor/corrector，而是做：

1. 给定当前接口猜测
2. reservoir solve
3. tail solve
4. 计算残差
5. 用 Aitken/under-relaxation 更新接口猜测
6. 若未收敛，继续下一轮

直到满足：

- `|dETA| < ETA_TOL`
- `|dQ| < Q_TOL`

或者达到最大迭代次数。

### 6.3 V21：低维隐式接口校正

如果 `V20` 仍然显著刚，则进一步引入“低维隐式接口校正”。

这一步不要求重写全局矩阵，但至少要把接口更新从简单松弛推进成：

- 基于当前/前一轮迭代构造的低维近似雅可比
- 或 secant / quasi-Newton 风格的界面更新

目标不是让整个 W2 变成 fully implicit global solver，而是：

- 让接口本身更像一个隐式求解层

## 7. 设计原则

### 7.1 不回退 V15-V17

方案 1 不是回到单段 tail domain，也不是回退到 branch-level transition。  
它必须建立在当前这些成果之上：

- 固定多段尾段域
- 逐段 state
- 逐段 transition-state

### 7.2 不在第一步就重写主矩阵

虽然最终最成熟的路线是更整体的 free-surface implicit coupling，但当前代码基础不适合第一步就重写主库区矩阵。  
因此方案 1 的实现路径是：

- 先显式化接口残差
- 再做强耦合界面迭代
- 最后才做低维隐式接口校正

### 7.3 先让“界面收敛”替代“时间步硬磨”

这是方案 1 的核心原则。  
只要界面残差还靠时间步慢慢磨掉，方法就还不够成熟。

## 8. 验收目标

### 8.1 V19 验收

- 新增接口残差 marker
- 能在 short/extended/long window 中追踪接口残差
- 能明确看到残差走势

### 8.2 V20 验收

- short/extended/long smoke 继续通过
- 每步内存在显式 interface iteration
- 接口迭代次数可统计
- 残差在大多数时间步内单调或准单调下降

### 8.3 V21 验收

- 功能不回退
- 短窗运行代价相对当前 `V18` 明显下降
- 长窗仍保持稳定

## 9. 与方案 3 的关系

方案 3 不是白做，它提供了一个很有价值的结论：

- 外围减载不能触及主刚性来源

这恰好给方案 1 指明了方向：  
后面真正要解决的，不是再少写日志、少跑 predictor，而是让接口本身更容易收敛。

## 10. 阶段性结论

方案 1 的本质，不是“更复杂”，而是“更正统”。

它把当前问题从：

- “怎么让分裂耦合少花一点时间”

转成：

- “怎么让接口本身更快收敛，从而不再依赖极小时间步”

如果 `V19-V21` 能按这条路线推进成功，那么我们对 W2 的改造就会从“功能拼接原型”真正迈向“成熟接口求解器原型”。
