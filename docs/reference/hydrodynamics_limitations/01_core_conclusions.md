# 01 核心结论

本页回答什么问题：对于你当前这个中间水库，CE-QUAL-W2 的水动力短板究竟在哪里，这些短板为什么会在变动回水场景里被放大，以及后续优化应把力气用在哪些地方。

## 一句话判断

你的直觉是对的：CE-QUAL-W2 可以模拟回水，但它的水动力主框架并不是为“低水位快流河道态”和“高水位淹没回水态”频繁切换的强非恒定回水过程而设计的，所以在这种工况下更容易表现出纵向前沿推进偏快、垂向响应偏硬。

## 已固定的硬结论

1. CE-QUAL-W2 的主水动力属于 laterally averaged、hydrostatic、free-surface implicit solve 加 velocity correction 的体系，而不是全耦合 dynamic-wave 网络求解。代码证据：`C1`、`C2`、`C7`；文献支撑：`L1`、`L2`、`L4`。

2. 模型并非完全不能做回水，问题在于它更擅长细长水体中的缓变回水，不擅长“回水末端迁移 + 下游顶托突变 + 结构物工况切换”同时出现的场景。代码证据：`C1`、`C3`、`C4`；文献支撑：`L1`、`L4`、`L8`。

3. 对你当前的单个中间水库而言，误差最主要不是来自横向平均本身，而是来自求解流程的分裂推进。水面先解、速度后修正、流量再靠 `QC` 校正补回，会让扰动更容易沿纵向提前传播。代码证据：`C1`；文献支撑：`L1`、`L2`、`L5`。

4. 结构物流量在自由出流和淹没出流之间按分段公式切换，是汛期切换误差最容易被放大的入口之一。代码证据：`C2`、`C3`；文献支撑：`L5`、`L8`。

5. 垂向速度 `W` 主要是由连续方程诊断出来的，不是通过独立的垂向动量方程预测出来的；再叠加 `AZ` 上下限和 `LAYERADDSUB` 阈值触发，垂向结构天然比较“硬”。代码证据：`C1`、`C5`、`C6`；文献支撑：`L1`、`L2`、`L4`。

6. 如果只研究一个中间水库，而不是整个四库系统，那么最有性价比的方向不是先换模型，而是先补强边界、结构物、局部耦合迭代和垂向闭合。文献支撑：`L5`、`L7`、`L8`；模型比较支撑：`L3`、`L4`。

## 对当前工程的具体解释

- 低水位泄洪期：更接近天然河道态，局部坡降、惯性项、结构物工况变化都会更敏感。W2 仍能算，但更依赖边界表达、网格分辨率和时间步控制。

- 高水位淹没期：更接近淹没回水态，模型对平缓水面线通常更稳，但一旦与泄洪态连续切换，边界翻转和结构物切换误差会快速累积。

- 季节切换期：这是最不容易做准的阶段。此时同一段河库过渡带既承担输水控制，又承担蓄水控制，单一固定参数和单次分裂推进很难同时兼顾两种制度。

## 为什么不把问题简单归咎于横向平均

- laterally averaged 假设确实会丢掉横向环流、回流和靠岸滞留区，但你已经判断横向平均并不是首要矛盾。

- 从代码和工况看，更直接的误差源是：边界更新过硬、内部水头映射直接、结构物流量分段切换、垂向闭合偏刚。

- 这意味着即使保留现有二维侧向平均框架，仍然有一条明确的优化路线可走。

## 当前推荐的总策略

- 保留 W2 作为主模型框架。

- 不再把重心放在水质删减本身，而是回到水动力主循环。

- 把改进优先级固定为：`P1` 每步内迭代耦合，`P2` 结构物流量平滑切换，`P3` 边界和内部水头松弛，`P4` 垂向混合与层调整迟滞，`P5` 切换带网格与时间步加密。

## 证据锚点

- `C1` `w2_main.f90`：主循环、自由液面解、速度修正、`QC` 校正、`W` 诊断。

- `C2` `hydroinout.F90`：源汇、结构物、内部外部边界入口。

- `C3` `gate-spill-pipe.f90`：堰流、孔流、淹没流分段切换。

- `C4` `waterbody.f90`：内部水体边界和剖面映射。

- `C5` `az.f90`：垂向湍混闭合与上下限钳制。

- `C6` `layeraddsub.F90`：层增减阈值和离散调整。

- `C7` `init-u-elws.f90`：正常水深初始化和初始流速设置。
