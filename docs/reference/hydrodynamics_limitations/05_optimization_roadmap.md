# 05 优化路线

本页回答什么问题：在不放弃 laterally averaged 框架、不回头扩展水质模块的前提下，应该优先改哪些地方、每项改动修什么问题、涉及哪些文件、预期收益和风险是什么。

## 总体策略

先补强“主水动力耦合 + 边界 + 结构物 + 垂向闭合”，后考虑更大尺度的模型替换。

对于你当前这个单个中间水库，最有性价比的是把 W2 改得更适应切换工况，而不是立刻走全局重构。

## 建议新增的运行参数

| 参数名 | 默认建议 | 作用 |
| --- | --- | --- |
| `HYDRO_INNER_ITERS` | `3` | 每步内水动力 Picard 迭代次数上限 |
| `HYDRO_ELWS_TOL` | `1.0E-4` 到 `1.0E-3` m | 水面收敛阈值 |
| `HYDRO_Q_TOL` | `1.0E-4` 到 `1.0E-3` 相对量级 | 流量收敛阈值 |
| `STRUCT_Q_RELAX` | `0.4` 到 `0.8` | 结构物流量欠松弛系数 |
| `STRUCT_SUBMERGENCE_BLEND` | `0.03` 到 `0.10` 的无量纲或局部水头比宽度 | 自由/淹没切换平滑带 |
| `BOUNDARY_HEAD_RELAX` | `0.3` 到 `0.8` | 内部或外部水头边界松弛系数 |

这些参数先作为规划接口保留，真正实现时可根据现有输入系统决定是否写进控制文件或模块常量。

## P1 每步内迭代耦合

### 修什么问题

主要修复纵向前沿传播偏快、水位和流速瞬时失配、结构物切换时边界与主水动力耦合不够紧的问题。

### 改哪里

- `C1` `w2_main.f90`

- `C2` `hydroinout.F90`

### 建议怎么改

- 在当前单次主水动力步内部包一层 Picard 迭代。

- 每次迭代重复执行：边界/结构物更新、自由液面解、几何更新、`U` 更新、`Q/QC` 比较与修正。

- 用 `ELWS` 最大变化、关键断面 `Q` 变化和结构物流量变化三重判据决定提前收敛。

### 为什么优先级最高

它直接对应你当前最显著的“纵向偏快”现象，而且能为后面的结构物平滑切换和边界松弛提供稳定的宿主框架。

### 可能副作用

- 计算时间上升。

- 现有自动时间步逻辑可能需要重新协调，避免内迭代和外层缩步打架。

## P2 结构物流量平滑切换

### 修什么问题

修复自由出流和淹没出流切换点附近的流量突跳、水位不连续和汛期切换误差放大。

### 改哪里

- `C2` `hydroinout.F90`

- `C3` `gate-spill-pipe.f90`

### 建议怎么改

- 把现有硬阈值切换改成在过渡带内进行 blending。

- 对本步新算出的结构物流量使用 `STRUCT_Q_RELAX` 做欠松弛。

- 保留原始经验公式本体，不先推翻公式，只改切换和更新方式。

### 为什么优先级高

结构物是切换工况里最容易引入非平滑误差的入口，而且修改范围相对集中，验证成本也比全局求解器改造低。

### 可能副作用

- 切换变平滑后，极端工况下峰值流量可能略有钝化，需要和实测或原公式能力线对照。

## P3 边界和内部水头松弛

### 修什么问题

修复下游顶托信号传播过硬、内部水头边界过快传导和 ghost cell 瞬时跳变的问题。

### 改哪里

- `C1` `w2_main.f90`

- `C4` `waterbody.f90`

### 建议怎么改

- 对内部和外部水头更新引入 `BOUNDARY_HEAD_RELAX`。

- 对跨水体映射后的关键状态量做有限松弛，而不是每步硬替换。

- 对快速泄洪期保留更严格的时间步控制，避免松弛掩盖真实信号。

### 为什么值得做

它是连接“单库研究对象”和“四库边界语境”的关键一环，能在不改整个网络框架的情况下缓和传播偏快。

### 可能副作用

- 松弛过强会把真实顶托传播拖慢，因此必须配合典型洪水过程做灵敏度试验。

## P4 垂向混合与层调整迟滞

### 修什么问题

修复垂向“锁层”“跳层”和对外部扰动响应偏硬的问题。

### 改哪里

- `C5` `az.f90`

- `C6` `layeraddsub.F90`

### 建议怎么改

- 让敏感河段的 `AZ` 更依赖局部剪切、稳定度和分层状态，而不是全域统一阈值。

- 对 `AZ` 的极小值和极大值控制加上更温和的过渡逻辑。

- 给加层减层判据加入迟滞和连续满足步数要求，减少频繁反复触发。

### 为什么值得做

它直接对应你观测到的“垂向死板”，而且不需要把垂向动量框架整体推倒重来。

### 可能副作用

- 参数空间会变大，标定难度提升。

- 某些原本稳定的案例可能需要重新校核。

## P5 网格与时间步针对性加密

### 修什么问题

修复切换带分辨率不足、前沿推进假扩散和局部梯度被平均掉的问题。

### 改哪里

- 输入网格与案例设置。

- 现有自动时间步控制策略。

### 建议怎么改

- 优先加密回水末端迁移带、坝前、结构物近区和温跃层附近。

- 保留全库主体网格不大改，避免把算力浪费在不敏感区。

- 泄洪期单独收紧时间步，不完全依赖默认自动步长。

### 为什么放在第五位

网格和时间步很重要，但如果 `P1` 到 `P4` 不先做，单纯细化网格通常只能把误差看得更清楚，未必能从机制上治好。

### 可能副作用

- 算时增长明显。

- 如果边界和结构物表达仍然过硬，细网格可能放大局部振荡。

## 推荐实施顺序

1. 先做 `P1`，把主循环耦合收紧。

2. 再做 `P2`，处理结构物切换。

3. 接着做 `P3`，缓和边界传播。

4. 然后做 `P4`，改善垂向响应。

5. 最后用 `P5` 做针对性加密和验证。

## 建议的验证场景

- 低水位泄洪河道态。

- 高水位淹没回水态。

- 汛期切换过程。

- 结构物自由/淹没切换过程。

## 建议的评价指标

- 水位峰值时差。

- 回水末端位置偏差。

- 纵向温度前沿到达时间偏差。

- 温跃层深度偏差。

- 垂向温度 RMSE。
