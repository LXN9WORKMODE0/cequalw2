# XLD 2021 实际案例水位与水面线再分析

本页回答什么问题：基于 `实际案例` 目录下已经完整跑完的模型输出，在已知 `SEG 222` 为坝前、`SEG 2` 为库尾上游边界的前提下，重新判断坝前水位误差、水面线切换过程和主要误差源。

## 1. 本页使用的判读前提

- `SEG 222` 是坝前控制段，对应 `el_obs2021.npt` 的坝前水位观测位置。
- `SEG 2` 是承接上游大坝的库尾边界。
- `wl.csv` 当前已输出到 `JDAY 44484.0`，即 `2021-10-15 00:00`。
- `el_obs2021.npt` 覆盖整个 2021 年，可以与本次完整输出直接重叠对比。
- distributed tributaries 仍然开启，且仍然是当前边界体系中的重要组成部分。

需要特别说明：本页结论替代了此前把 `SEG 122` 当作坝前控制段的临时判断，后续讨论应统一以 `SEG 222` 为坝前。

## 2. 坝前 `SEG 222` 的误差特征

### 2.1 全部重叠时段

将 `wl.csv` 中的 `SEG 222` 与 `el_obs2021.npt` 对比，`2021-08-22` 到 `2021-10-15` 的统计量为：

- `RMSE = 0.729 m`
- `MAE = 0.611 m`
- `Bias = -0.542 m`
- 最大正误差 `+1.104 m`
- 最大负误差 `-1.386 m`

这说明从完整时段看，坝前水位总体偏低，而且偏低已经不是几十分米量级，而是会放大到 1 米以上。

### 2.2 低水位向高水位切换的关键窗口

若只看你最关心的 `2021-08-22` 到 `2021-09-03`：

- `RMSE = 0.373 m`
- `MAE = 0.332 m`
- `Bias = -0.128 m`

对应的日均误差为：

最重要的事实是：

- `2021-08-27` 到 `2021-08-28` 之间，坝前误差由正转负。
- `2021-10-10` 到 `2021-10-11` 之间，坝前误差又由负转正。

因此当前误差不是“常数偏差”，而是非常明确的阶段性翻转误差。

## 3. 这次完整结果可以把过程分成三个阶段

### 阶段 A：河道态向回水态切换，模型先偏高

`2021-08-22` 到 `2021-08-27`

- 坝前模型水位先高于观测 `0.19` 到 `0.29 m`。
- 此时库尾 `SEG 2` 还未稳定连通，`2021-08-27 04:48` 才第一次由 `-999` 变为有效水位。
- `SEG 2` 首次变为有效时，`SEG 2 - SEG 222 = 7.937 m`，说明上游边界开始被回水显著淹没。

这一阶段最像“回水末端推进过快”。模型先把尾部连通和顶托影响提前带进来了，所以坝前水位在前半段抬得偏快。

### 阶段 B：快速蓄水阶段，模型转为显著偏低

`2021-08-28` 到大约 `2021-09-20`

- 坝前误差迅速转负，并在 `2021-09-10` 到 `2021-09-14` 左右达到最严重，日均误差约 `-1.24` 到 `-1.31 m`。
- 但这一段并不是“没水进库”。相反，`2021-09-08` 到 `2021-09-10` 的净入流非常强：

| 日期 | 主入流 | 支流+distributed | 出流 | 近似净入流 |
| --- | ---: | ---: | ---: | ---: |
| 2021-09-08 | 10229.6 | 877.1 | 6634.4 | +4472.3 |
| 2021-09-09 | 11800.0 | 932.5 | 8444.9 | +4287.6 |
| 2021-09-10 | 11893.8 | 729.4 | 11235.9 | +1387.3 |

而恰恰是在这段强净入流时期，坝前模拟水位比观测低了 1 米以上。

这说明后半段偏低不能简单解释为“来水不够”或“数值漏水”，更像是：

- 回水面推进后，有效蓄水范围张开得过早、过大。
- 同样的入库体积被分摊到更大的有效库容后，坝前水位上升速度反而偏慢。
- 换句话说，模型前面把回水推进得过快，后面又把库区“摊平”得过早。

### 阶段 C：高水位平库阶段，误差逐步收敛

`2021-09-21` 到 `2021-10-15`

- 坝前误差逐渐从 `-1 m` 左右回收。
- `2021-10-10` 时已经接近零偏差，`2021-10-11` 之后转为略偏高，`2021-10-15` 约 `+0.22 m`。

这说明在高水位稳定期，模型并不是完全失效，而是在“河道态到淹没回水态的切换过程”和“快速蓄水阶段”最脆弱。

## 4. 水面线本身非常支持“库尾切换过快”的判断

### 4.1 库尾连通的时间点

`SEG 2` 在 `2021-08-27 04:48` 首次变成有效值：

- `SEG 2 = 585.673 m`
- `SEG 222 = 577.736 m`
- 头差 `7.937 m`

这说明模型中库尾边界在该时刻才真正被主库回水连通。这个时点本身就与坝前误差由正向负翻转的窗口高度接近。

问题在于，模型把这个切换推进得太顺了、太快了。于是前半程坝前响应过快，后半程又因为有效蓄水面过早张开而抬不起来。

## 5. distributed 修正仍然是重要误差源，但不是全部答案

### 5.1 早期切换窗口中，distributed 修正非常激烈

在 `2021-08-22` 附近，distributed 修正存在明显尖峰：

- 最大正修正约 `+4278 m3/s`
- 最大负修正约 `-4359 m3/s`

这说明切换初期的边界修正非常强，会直接影响坝前水位与回水推进速度。

### 5.2 9 月上旬最严重低估期，distributed 仍然大，但已经不是唯一主导

在 `2021-09-06` 到 `2021-09-10`，5 条常规支流总入流约 `496 m3/s`，而 distributed 总修正为：

| 日期 | 常规 5 支流 | distributed 总修正 | 修正/常规比例 |
| --- | ---: | ---: | ---: |
| 2021-09-06 | 496.1 | 381.2 | 0.77 |
| 2021-09-07 | 496.1 | 457.1 | 0.92 |
| 2021-09-08 | 496.1 | 381.0 | 0.77 |
| 2021-09-09 | 496.1 | 436.4 | 0.88 |
| 2021-09-10 | 496.1 | 233.3 | 0.47 |

这依然很大，说明你说的“水位修正是根据坝前水位做的，会出现较大出入”是成立的。

但需要注意：

- 即使在 distributed 修正已经回落的 `2021-09-10` 以后，坝前偏低依然很严重。
- 所以 distributed 修正解释得了“前期被推偏”和“边界不稳定”，却解释不了全部的后期低估。

更合理的说法是：

- distributed 修正放大了误差。
- 真正让误差维持在 1 米级别的，是回水推进、库尾连通和有效库容响应之间的错配。

## 6. 数值上不是守恒坏了，而是物理闭合和传播方式有问题

`flowbal.csv` 里的 `%VOLerror` 量级大约为 `1e-9` 到 `1e-6`，说明：

- 当前 run 的数值体积守恒本身没有明显坏掉。
- 也就是说，问题不是“程序算着算着漏水了”。

但这不意味着边界水量就是可信的，因为：

- 5 条支流缺少实测，只能用多年平均再做月分配。
- distributed 修正又是根据坝前水位反推出来的经验修正项。

因此，这个案例更准确的表述应该是：

- 数值水量平衡是好的。
- 物理意义上的入流闭合仍然不够好。
- 一旦叠加河道态向回水态的切换，坝前误差就会被显著放大。

## 7. 完整 run 还暴露出一个后期数值敏感点：高水位期仍在频繁加减层

`w2.wrn` 显示，后期到 `JDAY 44479` 左右仍在重复：

- `Add layer 9`
- `Subtract layer 9`
- `Add layer 8`
- `Subtract layer 8`
- `Add/Subtract segments 245`

这说明即使进入高水位阶段，自由液面附近的层结构和局部湿干切换仍然比较敏感。

这类现象虽然不是坝前误差的第一原因，但会进一步放大高水位期的面积、体积和水位响应不连续。

## 8. 对“想不用 distributed 修正也尽量模拟好”这件事的直接启发

基于当前完整 run，我的判断是：

- 如果直接把 distributed 修正全部去掉，而不同时修正几何、边界和支流过程线，早期切换段大概率会更差，不会自动变好。
- 但如果目标是最终摆脱这种基于坝前水位反推的修正，那么最该优先提高的是“原始边界和几何表达能力”，而不是继续把 distributed 修正做得更强。

最值得优先改进的三个方向是：

1. `SEG 2` 到 `SEG 58` 的过渡带几何与糙率。
   这一段决定库尾何时由河道态切入回水态。

2. 5 条缺监测支流的过程线构造。
   月尺度分配太粗，会让涨水时序和库区蓄水响应都失真。

3. 库尾切换期的水动力推进方式。
   当前结果很像 W2 把库尾连通和平水化推进得过快，导致前高后低。

## 9. 当前案例的综合判断

现在可以把这个案例的结论说得更明确一些：

- `SEG 222` 的坝前模拟误差是一个明显的三阶段问题，不是单一偏差。
- `2021-08-22` 到 `2021-08-27`，模型先把回水影响推进得偏快，因此坝前偏高。
- `2021-08-28` 到 `2021-09-20` 左右，模型又把有效蓄水范围张开得偏早、偏大，因此坝前偏低，而且能低到 1 米以上。
- `2021-10` 以后随着主库整体趋于稳定平水，误差才逐步回收。
- distributed 修正是明显的重要误差源，但不是全部答案；更深层的问题仍然是回水推进、库尾连通和有效库容响应的错配。

因此，对你这个案例来说，最需要被控制的不是某一个静态参数，而是“库尾河流态向回水态切换的传播速度”。
